# 注入行为树

GM Console 的“注入行为树”页签用于编辑、保存与观察游戏内的一套 Lua 行为树。节点实现和目录随 Git 发布，新增节点只添加节点目录与脚本；标签用于搜索，基础类型与参数按目录决定。树数据不包含任意 Lua 源代码。目前登记23种节点：3组合、3装饰、12动作、5条件；预设中重复使用的节点是实例，不能按实例数计算能力种类。

## 运行预设

行为树直接使用 GM Console 左侧的客户端选择，不另设选择器、不自动选择。未选客户端、选了离线客户端或处于全部广播时不能运行，页签上方会给一行提示，仍可离线编辑。

页签上方的“运行准备”分两步，日常运行预设不需要打开下方的树编辑器：

1. **选择可执行目标**：按当前树实际需要的对象槽逐个列出，每个槽显示用于哪些节点和需要的能力。战斗玩家点“发现当前玩家”，GameObject 输入对象名称后搜索（最多返回 200 个）。候选卡显示名称、“战斗中”或场景编号与对象 ID、已有能力，以及“可控制”“只读”“不可用”和不可用的原因，点“选用”完成绑定。运行时目前不返回场景名和角色名，因此只显示编号。多个槽依次展开，已选槽显示所选目标，可更换或取消。未打开预设时可以先浏览目标，打开预设后在对应位置选用。
2. **预设与开始**：选择预设后核对“只读观察 / 会控制游戏”标签，再点开始。

目标只在你点击时才查找，不会自动发现，也不会自动绑定或替换目标。没有发现战斗玩家时，需要先进入战斗并等加载完成后再刷新。普攻类能力要求战斗正在进行：游戏停在暂停菜单、未进战斗或角色倒下时，目标会显示为“只读 / 不可用”并说明原因。已选目标旁的“重新读取状态”会重新读取它当前的能力，游戏处于暂停菜单时不要点，否则它会被读成只读。

已选目标之后若发现代次更新、对象失效、重新发现后消失，或启动时游戏返回绑定失效、能力不足，会在对应目标卡里用中文说明，并阻止开始，需要重新选择；不会静默改绑。其他操作失败的提示固定显示在运行准备上方，可关闭。对象名称本身不是跨场景身份，执行时仍由游戏重新验证完整绑定。

## 开始与观察

开始前先校验树，再在游戏内校验、安装，并等待游戏启动回执。树中所有节点都明确声明无副作用时才视为只读并直接开始；只要有节点会改变游戏状态，或节点未知、副作用缺省或无法识别，就按“会控制游戏”处理，开始前行内确认一次。

执行观测显示运行状态、停止或失败原因、清理错误和各节点状态。选择单个在线客户端并打开页签后，活跃运行每秒只读查询当前一份，约每5秒用轻量目录发现外部新运行；无活跃运行时放慢至3秒，网页进入后台时暂停轮询。自动发现客户端活跃运行，或恢复最近一次历史运行。实际运行图从客户端取回该次执行的树，不根据同名预设推测；与编辑器草稿分开显示。编辑草稿、布局及未完成的 JSON 输入保存在本浏览器，刷新后恢复，目标绑定不持久化。树始终在客户端独立执行，关闭、刷新或重开网页，以及客户端与控制台之间的传输断连，均不影响同一次运行；重新连通并打开网页后会读取当前运行状态。重连不自动重跑。客户端未支持实际树回读时提示更新运行器，不用预设代替。停止以游戏返回的当前 run 快照为准，网页请求断线或超时只报告未知，不能据此推断客户端已经停止。Unity Update 时钟不代表精确战斗逻辑帧。

普攻短按节点只等待指定技能开始，不等待命中或整段普攻结束。观察超时或操作条件丢失时返回失败，原因写入该节点的输出黑板；不会要求人工判断或悬挂运行。顺序节点遇到失败结束，选择节点可继续失败后的备选分支。节点仅提交一次短按，不自行重试。指定技能 ID 与角色、距离或当前连段不符时也会超时失败。

运行情况标题旁的“放大查看运行树”打开大弹窗，沿用同一份客户端状态；关闭或按 Esc 只关闭查看，不停止运行。运行图与编辑画布均支持鼠标位置锚定的滚轮缩放、拖动空白平移、Shift+滚轮横移；工具栏或 F 适应画布，0 还原100%。点击运行图节点可查看状态及原始参数，不能修改实际运行树。

会话 ID、运行 ID、已选目标的完整身份、运行时黑板、事件和错误原文在“高级诊断”中，默认折叠；展开才请求和渲染黑板、事件，逐节点列表同样按需渲染。树的初始黑板在树编辑器的“节点属性”里编辑（“初始黑板（JSON，可编辑）”）。

## 连续战斗

“接近最近敌人”按真实阵营关系、存活状态和血条筛选目标，通过普通摇杆靠近；离开、失败、超时或停止时释放本节点持有的移动输入。“战斗按键”提交普攻、当前最多同色可用球、闪避或可用必杀的正常按下／抬起；成功只表示完成一次按键，不依赖角色专属技能 ID。不可用时失败，可用选择节点转普攻或等待。连段节奏通过顺序、等待、选择和有限重复组合，不把整套自动战斗控制器包进一个动作。

“战斗导航”接受黑板中的世界目标点，先检查当前直线段，受阻时使用返回完整的 Detour 路径，并限制绕路长度。每段复核地形和端点，以实际位移及朝路点的净推进判断受阻；失败方向短期反馈给规划。地图/API未知、partial路径、超时或持续无进展会给出原因并释放本节点摇杆。动作锁定不计撞墙，入场输入通道未就绪也不会强行开启。它只验证当前地形与实际进展，不保证避开所有Npc碰撞或战斗判定。

## 识招、超算与资源恢复

“战斗观测”返回玩家和目标的血量、技能及技能帧、闪避资源比例、超算累计次数，以及按参数指定的双方 Buff 状态。`matrixReady` 表示极限闪避触发超算的条件，`dodgeEnergyRatio` 才是闪避资源；超算冷却期间仍可能正常闪避。角色模板可用数组列出同一角色的不同品质，关卡和目标模板也由树参数约束。

角色核心资源可通过可选 `playerAttributeIds` 请求最多16个整数属性索引；节点在额外读取前检查列表边界，默认不读。结果 `playerAttributes[字符串索引]` 分别给出 `known/value` 与 `maxKnown/max`，0仍是有效值；读取失败或非有限数保留未知并省略对应数值，不以0代替。每次生成独立快照。属性含义和动作门槛由当前分支源码与预设决定，不在观测节点硬编码角色。

“敌人技能窗口”按技能 ID、技能帧、距离和可选的正面夹角判断威胁。“近期技能”可按实际战斗帧判断连招窗口，不能用上一次按键提交代替实际起手。信号球条件和按键支持颜色、最小组数、预留后续颜色及优先小组；超算球是否可把单消转成三消，由游戏内真实 Buff 和技能结果确认。

移动节点支持靠近、远离和绕行。绕行会修正与目标的距离，并始终保留横向分量，帮助避免沿一条直线顶住障碍；它使用普通摇杆，不提供导航寻路。可移动期间默认连续10逻辑帧位移不足0.2时，写出 `no_movement` 并释放输入、返回失败；同节点短重入默认冷却10帧。`stuckFrames`、`minProgress`、`blockedRetryFrames` 可调整，技能锁移动、未知移动状态与未推进逻辑帧不计为受阻。这只是无进展反馈，树需用失败分支选择别的方向，尚不自动绕墙，也不保证落点安全。闪避可指定相对目标的方向，先准备方向、下一次 Update 再按键。节点停止、失败和被抢占时，仅释放本节点持有的输入。

资源恢复可以用观测、黑板比较、写黑板和组合节点编排。例如低于一个阈值进入恢复、高于另一个阈值退出，中间保持原状态。长时间运行的恢复分支和紧急防御选择应启用条件重新判断，使资源恢复或新威胁能够中断移动；多步按键与等待仍按顺序完成。玩家倒下时，战斗观测写出 `playerDead` 并返回失败，避免树继续空转。目标只有在未删除、明确死亡且真实生命可读并归零时才置 `finished`；限时清场只标死亡但仍有生命时返回失败，输出 `targetLifeKnown`、`targetLife`、`finishReason`。首次尚未发现敌人保留 `target_not_observed` 观察状态；已见目标失效不能冒充击杀。

“战斗观测”还提供角色动作、受击子状态、可控性、能否移动、实际技能帧、位置、独立的无敌/免伤状态及已知性，以及本次观测到的生命下降和距上次生命下降的逻辑帧数。受击FSM的CanControl会在其他动作下残留，只有处于BeHit且不能控制、或被抓住时才标为controlLocked；读取失败用controlKnown=false表示，不能解释为角色自由可动。观测只提供事实，不自行修改受击恢复策略。

角色/Boss预设可将受击恢复与资源恢复分别锁存：不可控期间抢占并清理本树输入，允许控制后按威胁选择脱离，满足接战条件再恢复输出。第一次命中后的硬直可能覆盖整套后续连击，不能把“受击恢复”当作可以绕过游戏门禁的解控。闪避已提交、实际起手、保护生效和规避成功也须分别记录。

“战斗计划”是只读动作：预设提供角色体积、速度及Boss招式/弹道模型，节点读取真实敌人、存活弹道、父载体位置和时间倍率，比较停留与有限走位候选。它分别给出已知性、危险时间、移动意图、候选目标和安全接战事实；缺少关键形状或寿命保持未知，过期Cast不在当前Boss位置重造。地形候选是有限采样，不能当作完整碰撞证明。业务招式可显式配置 `skills[].exitAcrossFacing=true`，优先从真实敌朝向的侧面/斜侧脱线；先过地形、当前目标体积及失败候选筛选，再在侧向池内比较原风险。侧向没有可用路线才回退，侧向全危险时仍可能没有安全方案，不能把这个偏好当安全证明。未启用该字段沿用原方向评分；已配置的当前目标体积也用于普通走位，避免计划穿体。 实际非重复弹道明确已对当前玩家消耗后，不再作为新的本体威胁；子弹道和后续Cast独立保留。可显式使用下一战斗帧的排队ToPosition作为该步出生锚，读取失败保持未知；启用前须核对目标更新相位，不把ToFacing或配表Move积分当作完整未来位移。

闪避可通过`directionPath`使用黑板世界方向。规划中的步行与闪避候选分开；可选的角色闪避包络用于比较恢复后仍会覆盖的判定，不把保护或精确落点当作已验证事实。角色动作参数、Boss技能和资源预算均由预设提供，不进入树内核。

防御分支应有失败后的等待/重观测出口，同时检查它确实能完成并重开动作：内层reactive选择可能每次重试都取消等待，造成导航超时后永久停留。外层仍可重新判断紧急威胁；需要完成的一次动作与短等待可用普通选择节点。输出距离应是有依据的区间，安全近身时先尝试输出，避免为凑精确距离环一直移动。

[红莲对卡穆的 4.9 调查与预设说明](lucia-camu-4.9.md) 展示这些通用节点的组合方式。角色连招、Boss 技能和资源阈值保存在预设中，未写入树内核。

## 编辑

树编辑器可以收起。画布支持拖动节点、输出圆点到节点的父子连线、点击连线断开、缩放与自动布局。大纲可用键盘选择节点，属性区可设置根、父节点、子节点顺序与参数。节点需要对象时，在参数里选择目标槽或点“新增一个目标槽”自动创建。所有视图编辑同一个树模型，未知节点保留但校验阻止运行。

点击顶部或“树编辑器”标题旁的“新开页签放大编辑”，会把当前草稿（包括无效 JSON 输入）和所选客户端带到独立页，编辑器使用完整页面宽度。新页签保存独立草稿，刷新可恢复，两页不会互相覆盖；预设共享，保存后可在原页重新打开。对象绑定不复制，需重新选择。独立页只读查询当前运行状态，编辑草稿不改变客户端正在执行的树。

运行没有网页续租，也没有内核默认最长运行时间。树成功、失败、主动停止、场景切换、目标失效或运行器卸载时结束，并清理本树输入。需要限定某段行为的时长时，在树中明确添加“超时”装饰节点；该节点仍按树的编排生效。开始前要求客户端运行器支持由树决定运行生命周期，旧版带隐含时限的运行器须更新后才能开始。

## 预设

预设独立存于 GM Console 的 `DATA_DIR/behavior_tree_presets.json`，不进入旧自定义 GM 数组。保存包括完整树、布局和 GameObject 的名称搜索条件，不保存游戏对象引用或永久实例 ID，也不为战斗玩家保存名称条件。重新打开预设后，如存在已保存的名称条件，目标区会出现“按预设记录自动匹配”，显式重新发现同来源的唯一可用目标并选用，随后请核对再开始。没有匹配或不唯一时要求手动选择。

导入先预览完整树与同一运行校验结果，可选择普通导入、另存副本或明确覆盖。未知节点可保存草稿，不会被删除；未知预设版本拒绝导入，不自动迁移。用户文件采用原子写回，写失败保留旧文件并报告错误。

部署 `sync-data` 白名单包含 `gm_console/custom_gm.json` 与 `gm_console/behavior_tree_presets.json`；同步为整文件覆盖，先备份目标文件并检查冲突。它不提供多人实时合并。单树分享优先使用导出/导入。
