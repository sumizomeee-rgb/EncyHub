# 红莲对卡穆：4.9 专项预设

预设 ID：`ency-lucia-camu49-reactive`。保存于 GM Console 的独立用户预设文件，按正常预设导入、打开和绑定流程使用。它针对囚笼体验版卡穆·骑士 `30300803`，玩家为红莲 `1021001`，允许品质对应的 `10210011` 至 `10210016` 模板，目标模板为 `83101`。入场、重登或场景改变后重新显式绑定。

## 调查依据

依据 `v4.9_review` 的以下配表和源码，使用同分支 Windows Debug 包验证。不是正式囚笼挑战，不消耗正式挑战次数。

- `Share/Fight/Behavior/Behavior/BehaviorNpcK001.tab`、`BehaviorNode/BehaviorNodeNpcK001.tab`：卡穆行为。
- `Share/Fight/Skill/Skill/SkillK001.tab`、`SkillKeyframe/SkillKeyframeK001.tab`：技能和 Cast 帧。
- `Share/Fight/Skill/Skill/SkillA.tab`、`Client/Character/Skill/CharacterSkillUpgradeDetail.tab`：红莲机制。
- `Share/Fight/FightConfig.tab`、`Buff/Buff/BuffA.tab`、`Behavior/Behavior/BehaviorEffectA.tab`：超算魔法、Buff 与行为。
- `XNpc.OnDodgeLimitCaster` 和 `XFightResult.Matrix`：只有实际触发超算才累计 `MatrixTimes`。`DodgeState.Activate` 与闪避资源是两个状态。

本分支 `XFightConfig.FPS=20`。Cast 帧是招式研究依据，伤害仍受弹道、距离和判定形状影响。输入由 Unity Update 调度，不能把静态窗口或一次按键当成精确命中证明。

## 角色与 Boss 机制

红莲实际任意三消后，四秒内再消红球进入双刀。普通三消对应红 `100203`、黄 `100206`、蓝 `100222`；双刀普攻为 `100214` 至 `100217`，突进为 `100232`，必杀为 `100207`。根据实际技能开始记录窗口，支持同一个技能对象的再次起手。

卡穆需区分格挡 `831011`、上挑与追加 `831006/831007`、连击 `831001/831002/831004/831005`、抓取 `831008`、脱离 `831013` 和爆气。预设用技能、帧、距离及朝向表达威胁，范围爆气不按正面限制。格挡期不主动攻击；连击期绕行，危险窗口才尝试正常闪避。

超算以真实累计次数与 Buff 交叉观测。红莲在该分支的超算球 Buff Kind 为 `1000720`，敌人减速 Buff Kind 为 `1000680`。优先用小组球利用超算三消并预留红球；没有可预留红球时仍可利用超算球造成三消，避免只等自然三消而浪费窗口。之后仍以实际三消和双刀起手确认连招。

## 受击恢复候选

另存预设`ency-lucia-camu49-hit-recovery-20261110`，保留原预设。完整基线采样发现：本账号/角色max闪避资源1000，实际每次闪避扣250；旧紧急门槛350会挡住资源296时可执行的二闪。831013保护期间的重复提交还会消耗下一招所需资源。这些是具体输入与实际技能起手对齐后的证据，不能由稀疏HTTP快照代替。

已实测的161节点版将紧急闪避门槛改为0.25；闪避100226实际无敌保护期间不重新安排输入，其他闪避分支也核对保护状态；四连击831005单独选择远离方向，其他招式保留侧闪。新增独立hitRecovering，受击硬直/被抓时不排进攻与移动，恢复控制后脱离。输入门禁消除了基线17次不可控期间闪避提交、24次保护内重复提交，但该版仍失败：受击恢复出口过于保守，压住超算输出，不能视作整体策略改善。

目前同ID保存为163节点“恢复出口修正（未实测）”：去掉受击恢复中重复的50%资源目标（资源由recovering独立管理），观测到敌人超算Buff时解除受击恢复；其他情况要求可移动、敌人无当前技能且10逻辑帧无新生命下降。离线真实Lua测试通过，包括资源100时在超算窗口重新到达普通输出；没有追加第三场实战，方向与退出条件的实战效果仍未证明。

基线36次生命下降全部发生在831005/831002期间，最终失败；受击FSM证明多段连吃期间不可控，所以修正重点仍是第一下之前的资源与保护时序。基线弹道枚举绑定缺口已修复，缺失证据不补造。候选运行结果另见当轮任务记录；不能从一次成功声称稳定无伤。

## 编排与验收

- 闪避资源低于 65% 时进入恢复，达到 80% 后退出，避免阈值附近反复接近和撤退。
- 恢复时绕行拉开，近身威胁且仍有资源时可以抢占移动，做一次紧急闪避。距离与阈值均为预设参数。
- 已触发超算时利用安全窗口；必杀已经起手时等待，不用移动或重复按键主动打断。
- 普攻、三消接红、双刀和必杀由条件与正常按键节点组成，不补战斗资源，不清公共输入队列，不启用强制输入或无敌。
- 树有有限循环与 280 秒保护超时。循环耗尽后仍检查 Boss 完成条件；不能把次数跑完记成击杀。死亡、对象失效和主动停止分别返回实际状态。

离线回归验证参数、事实读取、资源与超算状态分离、方向准备、冷却、绕行和清理；运行验收需另外检查技能序列、超算计数、双方血量和最终结算。试验中出现过失败轮次，不能从某一次成功起手或超算计数推断已经稳定通关。实际运行证据另存任务记录，不在工程文档保存测试账号和机器连接信息。
